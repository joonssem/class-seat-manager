# 01. 제품 요구사항 문서(PRD)

## 문서 목적

이 문서는 교사용 로컬 자리배치 Electron 앱의 제품 목표와 요구사항을 정의하는 단일 기준점이다. 구현 범위가 바뀌면 관련 설계 문서와 함께 갱신한다.

## 프로젝트 배경

담임교사는 학생의 교실 자리와 급식실 줄서기를 반복해서 정해야 한다. 단순 무작위 배치는 같은 학생이 같은 자리나 친구 주변을 반복 경험할 수 있고, 교사는 과거 이력을 수작업으로 기억해야 한다. 이 앱은 한 학년도 동안 누적된 자리 경험과 관계 정보를 활용해 설명 가능한 후보를 추천하고, 최종 판단은 교사가 내리도록 돕는다.

## 문제 정의

- 과거 자리·근접 경험을 기억하고 비교하기 어렵다.
- 랜덤 결과가 공정하고 다양한지 즉시 판단하기 어렵다.
- 학생별 위치 배려와 학생 pair 간 거리 조건을 수작업으로 반영하기 어렵다.
- 수업 중 빠른 자리 변경, 수정, 출력이 필요하지만 일반 웹서비스는 개인정보와 네트워크 의존성 부담이 있다.

## 제품 비전

교사가 학생의 다양한 공간 경험과 관계 경험을 장기적으로 관리하면서, 자동 추천과 교사의 전문적 판단이 자연스럽게 결합되는 오프라인 교실 운영 도구를 만든다.

## 목표

1. 한 학년도의 모든 확정 자리변경 이력을 보존한다.
2. 같은 자리·반복 근접·위치 경험 편중을 줄이는 후보를 추천한다.
3. 추천 근거와 위반 항목을 교사가 이해할 수 있게 보여준다.
4. 최종 확정 전까지 후보와 수정사항을 이력으로 저장하지 않는다.
5. 인터넷 없이 Windows PC에서 안정적으로 동작한다.

## 핵심 사용자와 사용자 요구

핵심 사용자는 한 학급을 맡은 담임교사 한 명이다. 교사는 학생 명단을 빠르게 등록·수정하고, 교실을 자유롭게 배치하며, 조건을 설정하고, 후보를 비교·수정·확정하고, 학생용/교사용 출력물을 만들어야 한다. 학생은 주 사용자가 아니며 전자칠판에 표시된 학생용 자리표를 소비한다.

## 핵심 사용자 시나리오

### 최초 사용

앱 실행 → 학년도 생성 → 학생 명단 입력 → 교실 구조 생성 → 책상 배치 → 위치 속성 확인 → 사용 시작.

### 자리 변경

새 자리 만들기 → 조건 확인 → 자동 계산 → 후보 3개 비교 → 하나 선택 → 교사 수동 수정 → 조건 재검사 → 확정 → 이력 저장 → 학생용 자리표 표시 → 필요 시 교사용 출력.

### 전입·전출

전입은 신규 학생과 전입일을 등록해 다음 배치부터 포함한다. 전출은 전출일과 재학 상태를 기록하고, 과거 이력은 유지하되 이후 자동배치 대상에서 제외한다.

### 급식실

급식실 → 현재 학기 인솔 학생 확인 → 새 줄서기 생성 → 결과 확인·수정 → 확정 → 줄서기·급식실 자리표 표시·출력.

## 기능 요구사항

| ID | 요구사항 | 필요한 이유 | 우선순위 |
|---|---|---|---|
| FR-01 | 학년도를 생성·전환·보관한다. 한국 학년도 날짜 범위를 사용한다. | 이력의 시간 경계를 명확히 하기 위해 | MVP |
| FR-02 | 학생을 직접 입력, 여러 줄 붙여넣기, CSV/Excel 가져오기로 등록한다. | 초기 입력 시간을 줄이기 위해 | MVP(Excel은 조건부) |
| FR-03 | 내부 `studentId`를 사용하고 출석번호를 PK로 사용하지 않는다. | 번호 변경·전입에도 이력을 보존하기 위해 | MVP |
| FR-04 | 재학·전출 상태, 전입일·전출일을 관리한다. | 현재 대상과 과거 기록을 분리하기 위해 | MVP |
| FR-05 | 책상·칠판·앞문·뒷문을 자유 배치하고 좌표를 저장한다. | 고정 격자가 아닌 실제 교실을 표현하기 위해 | MVP |
| FR-06 | 좌표에서 앞/중간/뒤, 왼쪽/가운데/오른쪽, 문 접근 태그를 계산하고 교사가 수정한다. | 공간 경험을 자리 ID 이상으로 관리하기 위해 | MVP 후반 |
| FR-07 | 수동 자리 배치와 드래그·교환을 지원한다. | 자동 추천을 교사의 판단으로 보정하기 위해 | MVP |
| FR-08 | 자동 후보를 생성하고 점수·세부 평가를 표시한다. | 추천 결과를 검토 가능하게 하기 위해 | MVP 후반 |
| FR-09 | 학생 위치 조건과 학생 pair 거리 조건을 저장·평가한다. | 개별 교육적·관계적 배려를 반영하기 위해 | Post-MVP/확장 MVP |
| FR-10 | 확정 배치만 `SeatingSession` 이력으로 저장한다. | 미확정 후보를 실제 착석으로 오인하지 않기 위해 | MVP |
| FR-11 | 학생별 자리 경험과 전체 통계를 조회한다. | 공정성과 다양성을 사후 점검하기 위해 | MVP 후반 |
| FR-12 | 급식실 줄서기, 22자리 배치, 학기별 인솔 학생 4명을 관리한다. | 별도 운영 규칙을 지원하기 위해 | Post-MVP |
| FR-13 | 학생용·교사용 교실 자리표와 급식실 줄서기·자리표를 인쇄/PDF 저장한다. | 현장 표시와 종이 사용을 위해 | MVP 후반 |
| FR-14 | 자동 저장, 단일 백업 내보내기·복원을 제공한다. | 로컬 데이터 손실을 줄이기 위해 | MVP |

## 비기능 요구사항

- 오프라인에서 핵심 기능이 동작한다.
- 일반 학급 20~30명, 약 50개 좌석 이내에서 후보 생성이 수 초 내 완료되도록 한다.
- Renderer는 DB와 Node API에 직접 접근하지 않는다.
- 모든 사용자 입력은 IPC 경계와 서비스 계층에서 검증한다.
- 자동 저장 실패·복원 실패·필수 조건 충돌을 이해 가능한 메시지로 알린다.
- 후보 생성은 seed와 설정을 남겨 테스트·재현 가능하게 한다.
- 이름은 정상 방향으로 출력하고 학생용/교사용 방향 규칙을 예측 가능하게 유지한다.

## 개인정보 처리 원칙

학생 이름·성별 등은 외부 서버, analytics, 외부 API로 보내지 않는다. 로컬 DB와 백업에 개인정보가 포함됨을 명시하고, 백업은 교사만 접근하는 안전한 위치에 보관하도록 안내한다. 운영 로그에는 이름 대신 내부 ID나 집계값만 기록하며 production debug log는 기본 비활성화한다. 학년도 데이터는 삭제 전 확인을 거치고, 백업 파일 삭제는 운영체제 파일 관리 책임임을 알린다.

암호화는 MVP에서 필수로 확정하지 않는다. 단일 교사·로컬 PC 사용을 전제로 파일 접근 권한과 백업 안내를 우선하고, 공유 PC·분실 장치 위험이 확인되면 백업 암호화와 DB 암호화를 Post-MVP로 검토한다.

## 로컬 우선 원칙

서버·로그인·클라우드 동기화 없이 모든 핵심 처리를 로컬에서 수행한다. OneDrive/USB 복사는 사용자가 운영체제에서 수행하며 앱은 자동 업로드나 동기화를 하지 않는다.

## MVP / 제외 범위

MVP는 학년도, 학생 관리, 교실 레이아웃, 수동 배치, 이력, 기본 자동 추천·설명, 기본 위치 경험, 출력, 백업/복원을 포함한다. 급식실, 고급 pair 조건, Excel 내보내기, 자동 업데이트, 암호화, 여러 학급·계정·서버·모바일·웹·실시간 동기화는 Post-MVP 또는 제외 범위다.

## 성공 기준

- 실제 학생 명단 없이도 샘플 학급으로 최초 설정부터 확정·복원까지 시연 가능하다.
- 확정 전 수정과 취소가 이력을 오염시키지 않는다.
- 전입·전출 처리 후 과거 기록과 통계가 깨지지 않는다.
- 교사가 후보 3개의 점수 구성과 조건 위반을 이해할 수 있다.
- 인터넷 차단 환경에서 학생·자리·출력·백업이 동작한다.

## 향후 확장 가능성

Excel 통계 내보내기, 사용자 정의 위치 태그, 급식실 고도화, 백업 암호화, 접근성 개선, 다중 학급, 업데이트 배포를 확장하되 핵심 도메인 모델과 엔진의 Electron 비의존성을 유지한다.
