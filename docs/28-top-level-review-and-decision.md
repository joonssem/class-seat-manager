# 최상위 계층 점검과 결정 (재작성 여부)

작성일: 2026-10-01

## 점검 방법
계획 문서(01 PRD, 04 엔진, 05 UI, 06 아키텍처, 08 로드맵, inbox, 23~26)를 구현과 비교했다.

## 결론: 처음부터 다시 만들지 않는다
- 06의 계층(domain → application → main/db → preload → renderer)이 구현과 일치한다. 엔진은 Electron 비의존 순수 TS이고 IPC는 zod로 검증한다.
- inbox의 첫 화면 P0/P1(준비 상태 표시, 기본 버튼)과 25번 UI 개선은 이미 적용되어 있다(23-uiux-implementation).
- 발견된 문제의 뿌리는 구조가 아니라 **04 문서의 근접 정의**였다. 구현이 문서를 충실히 따른 결과 옆자리가 "인접하지 않음"으로 평가됐다.

## 변경 순서(상위 → 하위)
1. 요구사항: FR-15(시선 기반 근접), FR-16(세로 모둠 옵션) 추가 — `01`
2. 엔진 설계: 근접 정의 개정, 모둠 항목 추가, 성별 가중치 40 — `04`
3. 로드맵: Phase 9b — `08`
4. 구현: `seat-proximity.ts`, `seat-groups.ts`, 엔진, IPC 옵션(`SeatingOptions`), 새 자리 화면 체크박스
5. 검증: 단위·화면·SQLite 통합 테스트(`npm run test:all`)

## 후속 작업 결과 (2026-10-01)
- 수동 수정 화면이 새 자리 화면의 모둠 옵션을 이어받아 같은 기준으로 재평가한다. 진입 직후 현재 점수도 계산한다.
- 후보 생성이 `generateCandidatesAsync`로 바뀌어 재시작 사이마다 이벤트 루프에 양보하고(앱이 멈추지 않음), 진행(n/12)을 표시하며, 취소 버튼으로 중단할 수 있다. 동기 `generateCandidates`와 같은 seed에서 같은 결과를 낸다.
- 테스트: 비동기 생성·취소, 수동 화면 옵션 전달, 새 자리 화면 취소.

## 남은 항목(계획 대비)
- 04의 단계별 lexicographic 비교는 hard 위반 우선 비교만 구현되어 있다.
- 시선 모델은 정사각 좌표·칠판 중앙 집중점 가정이다. 가중치는 사용 후 조정한다.
- 진행/취소의 IPC 경로(main→renderer 이벤트)는 자동 테스트가 없고 실행 확인이 필요하다.
- 학년도 전환·보관 화면(FR-01)은 만들지 않기로 결정했다. 해마다 학급 구성이 바뀌므로 학년도 간 이력 연속성이 필요 없고, 새 학년에는 새로 시작한다.
- 통계는 `자주 가까이 앉은 짝`까지 구현했다(bf37741). 인쇄 검증(Phase 12)은 실제 프린터/PDF 확인이 필요하다.

## 패키징 검증 (2026-10-01)
- `npm run package:win`이 처음에는 실패했다: `electron`이 `dependencies`에 있었다(electron-builder는 devDependencies만 허용). 이동 후 NSIS 설치 파일(`dist/학급 자리배치 도우미 Setup 0.1.0.exe`)이 생성된다.
- 패키징된 앱을 임시 userData(`--user-data-dir`)로 실행해 DB 파일이 생성되고 마이그레이션으로 테이블 15개가 만들어지는 것을 확인했다. `better_sqlite3.node`는 `app.asar.unpacked`에 포함된다.
- 미해결: 앱 아이콘 미설정(기본 Electron 아이콘), 코드 서명 없음(학교 PC 보안 경고 가능). 설치 후 실제 화면 동작은 직접 확인이 필요하다.
