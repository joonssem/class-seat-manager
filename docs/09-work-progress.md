# 작업 진행 기록

## 2026-09-01

### 기준 문서 확인

- `01-product-requirements.md`: 확정 자리배치 이력 보존, 학생용·교사용 출력, 인쇄/PDF를 MVP 범위로 확인했다.
- `03-data-model.md`: `SeatingSession`과 `SeatingAssignment`가 좌표 및 자리 이력의 기준 모델이다.
- `05-ui-ux-design.md`: 학생용은 칠판 기준, 교사용은 반대 방향으로 출력한다는 요구를 확인했다.
- `08-mvp-roadmap.md`: 자리표 출력은 별도 변환 모델과 fixture 테스트를 거쳐 검증해야 한다.

### 현재 구현과 기획의 차이

- 기존 구현은 교사용 자리표에서 좌우만 반전하고 있었다.
- 요구사항의 의미상 교사용 자리표는 교실 중심 기준 180도 점대칭이어야 한다.
- 점대칭 좌표 규칙은 다음과 같이 정의한다.

```text
x' = 1 - x - width
y' = 1 - y - height
```

- 칠판과 같은 교실 고정 요소도 표시 방향 규칙에 포함해야 한다.
- 학생 이름 자체는 회전하지 않고 정상 방향으로 표시한다.

### 관련 사용자 요청

자리표 화면의 학생용/교사용 화면이 좌우 선대칭으로 표시되는 문제를 수정한다. 단일 화면의 임시 CSS 수정으로 끝내지 않고 domain 좌표 변환, renderer 표시, 인쇄/PDF 결과, 테스트를 함께 검토한다.

### 수정 계획

1. 좌표 변환 규칙을 domain의 단일 함수로 확정한다.
2. 교사용 좌석과 칠판·문 등 고정 요소의 180도 변환 여부를 정한다.
3. 학생용/교사용 화면과 인쇄/PDF가 동일한 변환 결과를 사용하도록 연결한다.
4. 비정사각형 좌석을 포함한 점대칭 fixture 테스트를 추가한다.
5. 타입 검사 → 전체 테스트 → 빌드 → 실제 화면 확인 순서로 검증한다.
6. 기존 확정 이력의 snapshot 좌표는 변경하지 않고, 표시 시점에만 변환한다.

### 진행 원칙

- 한 번에 한 화면만 수정하지 않는다.
- 기획문서, 데이터 모델, domain, renderer, 출력, 테스트의 영향 범위를 먼저 확인한다.
- 구현 전 계획과 검증 결과를 이 문서에 계속 기록한다.

### 검증 결과

- 교사용 좌석 좌표의 좌우·상하 반전 및 점대칭 회귀 테스트 통과
- 타입 검사 통과
- 전체 테스트: 19개 통과, SQLite 통합 테스트 1개는 현재 Node ABI 환경에서 스킵
- 프로덕션 빌드 통과

### 180도 점대칭 수정 완료

- 교사용 좌석의 x/y 좌표를 모두 교실 중심 기준으로 변환했다.
- 비정사각형 좌석의 width/height를 보존하는 회귀 테스트를 추가했다.
- 교사용 칠판은 학생용 위치의 반대편인 하단에 표시하도록 수정했다.
- 학생 이름은 회전하지 않고 정상 방향으로 표시한다.
- 최종 검증: 타입 검사 통과, 테스트 20개 통과, SQLite 통합 테스트는 Node ABI 환경에서 스킵, 빌드 통과.

## 2026-09-01 추가 버그 접수: 첫 화면 이동 버튼 입력

### 사용자 보고

- 첫 번째 화면(대시보드)으로 이동하는 버튼에서 탭 입력이 동작하지 않는 현상이 테스트 중 보고되었다.
- 버그 접수 단계에서는 코드를 즉시 수정하지 않고, 영향 범위와 재현 조건을 먼저 기록한다.

### 전체 정적 점검 결과

- 학생 관리, 교실 설정, 수동 자리배치, 새 자리 만들기, 자리 기록, 조건 설정, 급식실, 급식실 기록, 백업 화면의 대시보드 이동 버튼은 `button type="button"`과 `onClick={onBack}` 구조다.
- 자리표의 `돌아가기`도 동일한 native button 구조이며, 진입 화면에 따라 반환 화면을 상태로 전달한다.
- 현재 확인된 코드에는 해당 버튼을 비활성화하는 `disabled`, `tabIndex=-1`, `pointer-events:none` 설정이 없다.
- 전역 버튼 CSS는 `cursor`와 hover 상태만 설정하며, 버튼 입력 자체를 차단하는 규칙은 확인되지 않았다.
- 자리표의 모드 전환 탭은 `<main>` 바깥에 렌더링되므로, 터치 좌표·포커스 순서·상위 레이아웃의 겹침 여부를 실제 화면에서 확인해야 한다.

### 원인 후보

1. 사용자가 말한 ‘탭’이 마우스/터치 탭인지, 키보드 Tab 포커스 이동인지 구분이 필요하다.
2. Electron 개발 환경의 창 포커스 또는 상위 요소 겹침으로 pointer/click 이벤트가 버튼까지 도달하지 않을 가능성이 있다.
3. 화면 전환 직후의 렌더링 또는 자리표 모드 전환 영역이 포커스를 가로채는지 확인해야 한다.
4. 각 화면별 `onBack` 반환 대상과 실제 기대 화면이 다른 경우를 입력 불능으로 오인할 수 있다.

### 수정 전 검증 계획

- 마우스 클릭, 터치 탭, 키보드 Tab 포커스 후 Enter/Space 입력을 각각 재현한다.
- 각 화면에서 버튼의 bounding box, `disabled`/`aria-disabled`, computed `pointer-events`, `z-index`, 포커스 순서를 확인한다.
- 대시보드 반환 버튼을 공통 컴포넌트/공통 동작으로 묶을지 결정한다.
- 화면 전환 상태와 버튼 입력 테스트를 먼저 추가한 뒤, 공통 입력 처리와 레이아웃을 일괄 수정한다.

### 현재 상태

- 문서 기록 및 영향 범위 점검만 완료했다.
- 코드 수정은 보류 중이다.

## 2026-09-01 추가 요구사항: 과거 자리 기록 입력

### 사용자 제공 데이터 형태

- 현재 2학기이므로 1학기 자리배치 기록을 별도로 입력할 수 있어야 한다.
- 과거 기록은 `학생 이름 + 자리 번호`로 구성되어 있다.
- 과거 기록의 자리 번호는 현재 테스트 중인 교실 자리 번호와 일치한다.
- 3월부터 7월까지 1학기 동안 총 5회 자리배치를 수정했다.
- 따라서 과거 데이터는 1개의 현재 상태가 아니라 1학기 1~5회차의 연속된 기록으로 입력해야 한다.

### 필요한 사용자 흐름

1. 자리 기록 화면에서 `과거 기록 입력`을 선택한다.
2. 학기를 1학기로 지정하고 실제 배치일을 입력한다.
3. 학생 이름과 자리 번호 목록을 붙여넣거나 행 단위로 입력한다.
4. 현재 학생 명단의 이름과 연결하고, 현재 교실 layout의 자리 번호와 대조한다.
5. 미등록 학생, 중복 이름, 존재하지 않는 자리 번호, 중복 자리 배정을 검토 경고로 표시한다.
6. 검증을 통과한 기록만 확정 `SeatingSession`/`SeatingAssignment`로 저장한다.

### 과거 회차 구성

| 구분 | 값 |
|---|---|
| 학기 | 1학기 |
| 기록 수 | 5회 |
| 기간 | 3월~7월 |
| 회차 | 1차, 2차, 3차, 4차, 5차 |
| 입력 데이터 | 각 회차별 학생 이름 + 자리 번호 |
| 자리 기준 | 현재 테스트 교실의 자리번호와 동일 |

- 각 회차는 별도의 확정 session으로 저장한다.
- 회차 순서는 입력 순서가 아니라 실제 배치일 기준으로 확인한다.
- 날짜를 정확히 모르는 회차는 임의 날짜로 저장하지 않고, 사용자가 확인할 수 있는 상태로 둔다.
- 1학기 5회 기록이 저장된 뒤 2학기 새 기록은 별도의 회차 흐름으로 이어진다.

### 데이터 연결 원칙

- 저장 시 학생 이름을 primary key로 사용하지 않고 현재 학생의 `studentId`로 연결한다.
- 자리 번호는 현재 layout의 `seatCode` 또는 자리 ID와 매칭한다.
- 과거 기록의 학생 이름과 자리 번호는 assignment snapshot에도 보존한다.
- 현재 자리번호가 과거 기록과 일치하므로 좌표를 새로 매핑하거나 임의로 재배치하지 않는다.
- 기존 확정 기록과 동일한 날짜·학기·회차를 중복 저장하지 않도록 확인한다.

### 수정 계획에 추가할 범위

- 과거 기록 입력 UI/붙여넣기 형식 정의
- 이름→studentId, 자리번호→seatId 매칭 검증 로직
- 1학기 과거 기록용 확정 저장 경로
- 저장 전 미리보기와 오류 행 표시
- 가져온 기록이 자동 자리추천 이력과 학생별 경험 통계에 반영되는지 검증

### 현재 상태

- 요구사항과 데이터 매칭 규칙만 문서에 반영했다.
- 코드 수정은 보류 중이다.
