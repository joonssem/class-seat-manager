# 학급 자리배치 도우미 — UI/UX 개선 지시서 (Codex 실행용)

## 0. 이 문서의 사용법

너는 Electron + React + TypeScript로 만들어진 데스크톱 앱 "학급 자리배치 도우미"의 UI/UX를 개선하는 프론트엔드 작업자다.
이 지시서는 코드베이스를 보지 않은 상태에서 작성되었다. 실제 코드 구조와 이 문서가 충돌하면 **코드의 실제 구조를 우선**하고, 어긋난 부분을 보고서에 기록한다.

### 작업 전 필수 절차 (코드를 수정하기 전에 반드시 먼저 수행)

1. 저장소 구조를 조사해서 다음을 파악하고, **짧은 요약을 먼저 출력한 뒤** 작업을 시작한다.
   - 렌더러 진입점, 라우팅 방식(react-router / 자체 상태 기반 화면 전환 등)
   - 상태 관리 방식(Context / Zustand / Redux / 로컬 state)
   - 스타일링 방식(CSS Modules / styled-components / Tailwind / 전역 CSS)
   - 이미 존재하는 공통 컴포넌트(Button, Modal, Toast 등)와 그 위치
   - 좌석·학생·자리배치 데이터 모델의 실제 필드명 (특히 학년도, 반, 차수, 확정일, 좌석 번호)
   - 인쇄/PDF 저장이 구현된 방식 (window.print / Electron printToPDF / 별도 인쇄 뷰)
   - `package.json`의 실제 스크립트명 (typecheck / lint / test / build)
2. 기존 스타일링 스택을 그대로 따른다. **새 UI 라이브러리(MUI, Chakra, shadcn 등)나 CSS 프레임워크를 새로 도입하지 않는다.** 이미 설치되어 있다면 그것을 활용한다.
3. 아이콘이 필요한데 아이콘 라이브러리가 없다면, 인라인 SVG를 직접 작성한다.

### 절대 하지 말 것

- 기능 추가·삭제, 화면 신설, 비즈니스 로직 변경
- 자리배치 알고리즘, 점수 계산 로직, 데이터 스키마, 저장 포맷 변경
- 기존 저장 데이터와의 호환성을 깨는 변경 (좌석 번호 체계 포함)
- 이번 작업 범위 밖의 리팩터링(폴더 구조 전면 개편, 상태관리 교체 등)

이 작업의 목표는 **기존 기능을 더 명확하고 안전하고 읽기 쉽게 만드는 것**이다. 기능 추가보다 명확성·안정성·접근성이 우선이다.

## 1. 제품과 사용자

- 제품: 초등학교 담임교사가 학급 자리배치를 만들고, 확정하고, 인쇄해서 교실에 붙이는 데스크톱 앱
- 주 사용자: 초등학교 담임교사 (마우스 중심, PC 사용)
- 사용 맥락: 학기 초·자리 변경 시점에 **짧고 집중하기 어려운 상황**에서 사용
- 사용자 특성: 디자인 도구나 복잡한 설정 화면에 익숙하지 않을 수 있음

따라서 다음을 피한다: 전문 용어, 과도한 선택지, 작은 글자, 아이콘만으로 의미를 전달하는 UI, 설명 없는 숫자.

### 디자인 최우선 목표 세 가지

1. 사용자가 **지금 해야 할 다음 행동**을 즉시 알 수 있다.
2. 자리 배치 과정에서 **실수하거나 작업 내용을 잃지 않는다.**
3. 학생 명단 → 자리표 → 배치 조건 → 결과 평가가 **한 흐름으로 이해된다.**

### 2.2 공통 규칙 (시안과 무관하게 동일)

- 모든 색은 CSS 변수로 정의한다. 단일 파일(예: `src/styles/tokens.css`)에 모으고, 컴포넌트에서 **hex 하드코딩 금지**.
- 한 화면에 강조 색은 하나만. 포인트 색은 primary action에만 쓴다.
- 색만으로 상태를 전달하지 않는다. 상태에는 **아이콘 또는 텍스트 라벨을 항상 함께** 붙인다.
- 장식용 그라데이션, 큰 그림자, 자동 재생 애니메이션을 쓰지 않는다. 그림자는 오버레이(모달·토스트·드롭다운)에만 사용하고, 카드는 `--border` 1px로 구분한다.
- 모션은 사용자 행동에 대한 응답에만 사용하고 150~200ms 이내로 짧게. `prefers-reduced-motion: reduce`를 존중한다.

**타이포그래피**

- 폰트 스택: `"Pretendard Variable", Pretendard, -apple-system, "Segoe UI", "Malgun Gothic", "Apple SD Gothic Neo", sans-serif` (Pretendard가 이미 번들에 없다면 새로 추가하지 말고 시스템 폰트 스택만 사용)
- 스케일: 12 / 13 / 14 / 16 / 18 / 20 / 24 / 30 px. **본문 기본 16px**, 보조 설명 14px, 12px는 뱃지·표 캡션 등 최소 범위에만.
- 줄 간격: 본문 1.6, 제목 1.3. 문단 최대 너비 70~80자.
- 굵기는 400 / 600 / 700 세 단계만 사용. 대문자 변환(`text-transform: uppercase`)과 자간 확대 라벨은 쓰지 않는다.
- 중요한 정보를 작은 회색 글씨에 숨기지 않는다. 준비 상태, 저장 상태, 조건 위반은 본문 크기로 표시한다.

**간격·모서리**

- 간격은 4px 배수만 사용: 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48
- 카드 내부 패딩 20~24px, 카드 사이 간격 16px, 섹션 사이 32px
- 모서리: 입력·버튼 8px, 카드 12px, 좌석 셀 6px, 뱃지 999px
- 클릭 가능한 요소 최소 크기 36px 높이(주요 버튼 40px), 좌석 셀 최소 56×48px

### 2.3 공통 컴포넌트

아래 컴포넌트를 만들고(또는 기존 것을 이 규격에 맞게 정리하고) **모든 화면이 이것만 사용**하도록 통일한다.

| 컴포넌트 | 규격 |
|---|---|
| `Button` | variant: `primary` / `secondary` / `ghost` / `danger`, size: `md`(기본, 40px) / `sm`(32px). `loading` 시 스피너 표시 + `disabled` 처리로 중복 클릭 차단. `disabled`일 때는 이유를 `title` 또는 인접 텍스트로 반드시 설명 |
| `Card` | 1px `--border`, radius 12, `--surface` 배경. 제목·설명·본문·액션 영역 슬롯 |
| `SectionHeader` | 제목(18~20px, 600) + 한 줄 설명(14px, `--text-muted`) |
| `StatusBanner` | tone: `info` / `success` / `warning` / `danger`. 아이콘 + 문장 + (선택) 인라인 액션 버튼 |
| `StatusPill` | 좌석·조건 상태 표시용. 색 + 짧은 텍스트 함께 |
| `Toast` | 저장·완료 알림. 4초 후 자동 사라짐, `role="status"` |
| `ConfirmDialog` | 되돌리기 어려운 행동 전용. 제목·결과 설명·`danger` 확인 버튼·취소 버튼. 포커스 트랩, ESC 닫기 |
| `SegmentedControl` | 학생용/교사용 전환 등. 선택 상태를 색 + 굵기 + 테두리로 표시, `role="tablist"` |
| `EmptyState` | 아이콘/제목/한 문장 설명/행동 버튼 1개 |
| `InlineError` | 입력 요소 바로 아래, `--danger`, `aria-describedby`로 연결 |
| `SeatCell` | 좌석 번호 + 학생 이름. 상태: 기본 / 빈자리 / 선택됨(1차) / 선택됨(2차) / 조건 위반 / 강조. **각 상태는 색 + 테두리 + 텍스트나 아이콘 세 가지로 동시에 구분** |

**버튼 원칙**

- 한 화면의 primary 버튼은 **정확히 하나**. 작업 후 각 화면을 훑어 primary가 둘 이상이면 낮춘다.
- "삭제", "초기화", "전출 처리"는 `danger` + `ConfirmDialog` 필수.
- 버튼 이름은 결과가 드러나게 쓴다. "생성", "확인", "제출" 금지 → "후보 생성", "이 후보로 수동 수정하기", "자리표 저장", "현재 자리표 열기".
- 버튼 이름과 결과 메시지의 동사를 일치시킨다. "확정 저장" 버튼 → "저장되었습니다" 토스트.

## 3. 화면별 개선 요구사항

각 화면마다 **빈 상태 / 로딩 중 / 오류 상태**를 반드시 설계한다. 진행 중에는 진행 표시를 보여주고 중복 클릭을 막는다.

### 3.1 대시보드

기능 목록이 아니라 **자리 배치 작업의 시작점**이어야 한다.

화면 상단부터 이 순서로 보여준다.

1. 현재 학년도 (데이터 모델에 반 정보가 있으면 함께)
2. 준비 상태: 학생 명단 등록 여부, 교실 좌석 설정 여부
3. 가장 중요한 다음 행동 하나
4. 최근 확정 자리표와 확정일

요구사항:

- 상단 상태 영역은 현재 상태와 다음 행동을 **한 문장**으로 설명한다.
  - 준비 완료: "학생 24명과 좌석 24개가 준비되었습니다. 새 자리배치를 만들 수 있습니다."
  - 준비 부족: "학생 명단이 아직 없습니다. 명단을 먼저 등록해 주세요."
- 준비가 부족할 때 버튼만 비활성화하지 않는다. 부족한 항목을 **바로 해결하는 버튼**을 그 자리에 둔다. ("학생 명단 등록하기", "교실 좌석 설정하기")
- "준비 설정" / "현재 자리" / "기록 및 기타" 세 그룹의 위계를 시각적으로 분명히 한다. 모든 카드의 버튼이 똑같이 강해 보이면 안 된다. primary는 화면 전체에서 하나.
- 최근 확정 자리표가 있으면 작은 요약 대신 **자리표 미리보기(축소 그리드)** 또는 핵심 요약(확정일, 배치 학생 수)을 보여주고 "자리표 보기" 버튼을 붙인다.
- 급식실 배치, 백업/복원처럼 사용 빈도가 낮은 기능은 화면 하단 보조 영역에 secondary 스타일로 둔다.

### 3.2 새 자리 만들기 (자동 후보 생성)

자동 추천 결과를 **이해하고 선택**하는 핵심 화면이다.

레이아웃: 상단 = 후보 생성 버튼과 생성 상태 / 중앙 = 큰 자리표 / 우측 = 선택 후보의 점수와 조건 평가 / 하단 = 다음 단계 버튼

요구사항:

- 첫 진입 시(후보 없음) `EmptyState`로 안내한다.
  - "후보 생성을 누르면 과거 자리와 설정한 조건을 반영한 추천안을 만듭니다."
- "후보 생성"은 화면에서 가장 눈에 띄는 primary 버튼. 생성 중에는 로딩 표시 + 버튼 비활성화.
- 후보 A/B/C는 점수만 보여주지 말고 **한 줄 성격 설명**을 함께 붙인다. 문구는 실제 생성 로직을 코드에서 확인한 뒤 그에 맞게 정한다. (예: "가장 균형 잡힌 배치", "짝 조건 우선", "자리 반복 최소화")
- 점수의 의미를 한 문장으로 설명한다. **코드의 실제 점수 방향을 확인하고 정확하게 쓸 것.** (예: 낮을수록 좋은 경우 → "점수가 낮을수록 조건 충돌과 자리 반복이 적습니다.")
- 자리표에서 두 좌석을 골라 학생을 교체하는 방식은 단계별로 안내한다.
  - 선택 전: "교체할 첫 번째 자리를 선택하세요."
  - 첫 좌석 선택 후: "교체할 두 번째 자리를 선택하세요." + 선택 취소 버튼
  - 선택된 좌석은 색 + 테두리 + 텍스트("1번째 선택")로 동시에 표시
- 조건 평가 목록은 세 상태로 묶어 정리한다: **문제 없음 / 확인 필요 / 반드시 수정 필요**. 각 항목은 학생 이름이 들어간 이해 가능한 문장으로 쓴다.
- 세부 점수 항목은 기본 화면에 늘어놓지 말고 "평가 상세 보기"로 접어 둔다.
- 하단 버튼은 결과가 드러나게: "이 후보로 수동 수정하기".

### 3.3 수동 자리 수정

실수가 가장 쉽게 발생하는 화면이다. **현재 무엇을 편집 중인지, 저장되었는지**를 항상 보이게 한다.

- 화면 상단 고정 영역에 작업 상태를 표시한다. "후보 A를 수정 중 · 저장되지 않은 변경사항 있음"
- 저장 상태는 색만이 아니라 텍스트로도 구분한다: "모든 변경사항이 저장됨" / "저장되지 않은 변경사항 3건"
- 좌석 교체 방법을 항상 짧게 안내한다(3.2와 동일한 문구 사용).
- 선택된 학생과 선택된 좌석을 분명히 강조한다.
- 조건 위반은 **즉시**, 이해 가능한 문장으로 알린다. "민수와 지우는 '멀리 앉기' 조건이 충족되지 않았습니다."
- "미리보기"와 "확정 저장"을 분리한다. 확정 저장이 이 화면의 유일한 primary.
- 저장 성공 시 토스트: "2026년 2학기 3차 자리배치로 저장되었습니다." (실제 차수·학기 필드명을 코드에서 확인해 사용)
- 저장하지 않은 변경사항이 있는 상태에서 대시보드 이동·창 닫기를 시도하면 `ConfirmDialog`로 확인한다. "저장하지 않은 수정 사항이 있습니다. 나가면 변경 내용이 사라집니다."

### 3.4 자리표 보기 · 인쇄

교실에서 바로 쓰는 결과물이다. 화면과 인쇄물 모두 단순해야 한다.

- 상단에 학생용/교사용 전환을 `SegmentedControl`로 제공한다.
- 현재 보기 방향을 쉬운 문장으로 설명한다.
  - 학생용: "칠판을 바라보는 학생 기준"
  - 교사용: "교실 뒤에서 학생을 바라보는 교사 기준"
- "인쇄 / PDF 저장" 버튼을 상단의 분명한 위치에 둔다.
- 학생용 자리표에는 교사용 정보나 조건 점수를 절대 노출하지 않는다.
- 좌석 번호는 작게, 학생 이름은 크고 진하게. 이름과 배경 대비를 충분히 확보한다.

**인쇄 CSS 요구사항**

- `@media print`에서 앱 헤더, 사이드바, 안내 문구, 전환 버튼, 스크롤바를 숨긴다.
- `@page { size: A4; margin: 12mm; }` 기준으로 잡되, 좌석 수가 많으면 가로 방향도 확인한다.
- 인쇄물 상단에 학년도, (있다면) 반 정보, 자리배치 날짜 또는 차수를 한 줄로 넣는다.
- 좌석 이름은 인쇄 시 최소 12pt 이상. 좌석 격자는 배경색 대신 **테두리**로 구분한다(잉크 절약, 흑백 출력 대응).
- 자리표가 페이지 중간에서 잘리지 않도록 `break-inside: avoid` 처리.

### 3.5 학생 관리

- "학생 추가"와 "명단 붙여넣기"를 시각적으로 분명히 구분한다(별도 카드 또는 탭).
- 붙여넣기 입력에는 지원 형식을 **실제 예시 텍스트**로 보여준다.
- 오류 메시지는 입력 영역 바로 아래에 `InlineError`로 표시한다. 몇 번째 줄이 문제인지 알려준다.
- 학생 수와 등록 상태를 표 상단에 명확히 표시한다. "총 24명 등록됨"
- 전출 처리는 `danger` + `ConfirmDialog`. 확인 문구에 결과를 설명한다. "전출 처리하면 앞으로의 자리배치에서 제외됩니다."

### 3.6 교실 편집

- 좌석 배치 방법과 저장 방법을 화면 상단에서 한두 문장으로 안내한다.
- 칠판, 문, 책상 등 요소의 의미를 **범례**로 제공한다(호버 툴팁만으로 처리하지 않는다).
- 좌석 번호가 과거 기록과 연결되므로, 기존 좌석 삭제·번호 변경 시 경고를 표시한다. "이 좌석 번호는 지난 자리 기록에 사용되었습니다. 변경하면 과거 기록과 연결이 끊길 수 있습니다."
- 저장되지 않은 변경사항을 3.3과 동일한 방식으로 표시하고, 이탈 시 확인한다.

## 4. 문구 작성 규칙

- 능동태, 평서형, 사용자의 말로 쓴다. 시스템 내부 용어("객체", "인스턴스", "정규화")를 노출하지 않는다.
- 오류는 사과하지 않고, 무엇이 잘못됐고 어떻게 고치는지 말한다.
  - 나쁨: "오류가 발생했습니다." / 좋음: "3번째 줄의 이름이 비어 있습니다. 이름을 입력한 뒤 다시 붙여넣어 주세요."
- 빈 화면은 안내가 아니라 **행동 제안**이다.
- 같은 행동은 어디서나 같은 이름으로 부른다. 용어 사전을 만들어 일관되게 쓴다: 자리배치 / 후보 / 조건 / 확정 저장 / 자리표 / 차수.
- 존댓말 종결 어미로 통일한다("~합니다", "~하세요"). 느낌표는 쓰지 않는다.

---

## 5. 접근성 품질 기준

- 모든 버튼·입력·좌석은 Tab으로 이동, Enter/Space로 실행 가능해야 한다.
- 포커스 링을 절대 제거하지 않는다. `outline: 2px solid var(--focus); outline-offset: 2px`를 전역 `:focus-visible`에 적용한다.
- 선택된 탭·좌석·보기 모드는 색 외에 테두리, 굵기, 아이콘, 텍스트 중 하나 이상으로도 구분되어야 한다.
- 아이콘만 있는 버튼에는 `aria-label`을 반드시 붙인다.
- 오류 메시지는 `role="alert"`, 저장 완료 등 상태 알림은 `role="status"`로 스크린 리더에 전달한다.
- 모달은 포커스 트랩 + ESC 닫기 + 닫은 뒤 원래 요소로 포커스 복귀.
- 텍스트 대비 4.5:1 이상, UI 요소·큰 텍스트 3:1 이상. **구현 후 실제 값으로 검증한다.**
- 창을 1024×720까지 줄여도 핵심 행동 버튼과 자리표가 잘리지 않아야 한다. 자리표는 필요하면 가로 스크롤 컨테이너로 감싸되, 액션 버튼은 항상 보이게 한다.

## 6. 작업 순서

1. 코드베이스 조사 결과와 현재 화면별 문제점을 짧게 정리해 출력한다.
2. 디자인 토큰 파일과 공통 컴포넌트를 먼저 만든다. (색상, 간격, 타이포, Button, Card, StatusBanner, Toast, ConfirmDialog, SegmentedControl, EmptyState, SeatCell)
3. 화면을 이 순서로 개선한다: **대시보드 → 새 자리 만들기 → 수동 수정 → 자리표 보기·인쇄 → 학생 관리 → 교실 편집**
4. 각 화면을 다시 훑으며 primary action이 하나인지 확인한다.
5. 키보드 접근성, 오류 상태, 저장 상태, 작은 창 크기, 인쇄 미리보기를 점검한다.
6. 단계마다 논리적 단위로 커밋한다(토큰/공통 컴포넌트/화면별).

## 7. 검증

`package.json`에서 실제 스크립트명을 확인한 뒤 실행하고, 모두 통과시킨다.

- 타입 검사 (`tsc --noEmit` 또는 해당 스크립트)
- 린트
- 테스트 (기존 테스트가 깨지면 원인을 밝히고 고친다. 테스트를 지우거나 skip 처리하지 않는다.)
- 프로덕션 빌드

수동 확인 체크리스트도 직접 점검한다.

- [ ] 학생 0명 / 좌석 0개 상태에서 대시보드가 다음 행동을 안내하는가
- [ ] 후보 생성 중 버튼 중복 클릭이 막히는가
- [ ] 좌석 두 개 선택 → 교체 흐름이 안내 문구만으로 이해되는가
- [ ] 저장하지 않고 나가려 할 때 확인 대화상자가 뜨는가
- [ ] 마우스를 쓰지 않고 Tab만으로 대시보드 → 후보 생성 → 수동 수정까지 도달 가능한가
- [ ] 인쇄 미리보기에 앱 UI가 남아 있지 않은가
- [ ] 학생용 자리표에 점수·조건 정보가 노출되지 않는가
- [ ] 창을 1024×720으로 줄였을 때 primary 버튼이 보이는가

## 8. 완료 기준

- 처음 쓰는 교사가 대시보드에서 자리배치 시작 방법을 10초 안에 이해한다.
- 후보 생성 → 후보 선택 → 좌석 교체 → 수동 수정 이동의 흐름이 별도 설명 없이 이해된다.
- 저장 여부와 조건 위반 여부를 놓치기 어렵다.
- 인쇄된 자리표가 교실에서 바로 쓸 수 있을 만큼 단순하고 읽기 쉽다.

## 9. 최종 보고 형식

작업을 마치면 다음을 정리해 출력한다.

1. 선택한 색상 시안(A/B/C)과 그 이유 — 한 줄
2. 변경한 파일 목록과 각 파일에서 한 일 — 한 줄씩
3. 화면별 주요 UX 결정 사항과 근거 — 화면당 2~3줄
4. 이 지시서와 실제 코드가 달라 다르게 처리한 부분
5. 확인이 필요한 사항(데이터 모델에 반 정보·차수가 없어서 생략한 표시 등)
6. 검증 명령 실행 결과
7. 후속 작업으로 남긴 것
